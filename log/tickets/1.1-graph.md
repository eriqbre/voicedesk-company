## User-visible behavior

Eriq (Google connected, cache warm) says **“What’s going on with Beach Drive?”** (or the listing address / a known street fragment).

1. Voice narrates the situation in a few sentences: latest mail, who is in it, next showing if one exists. No recitation dump. No invented people or events.
2. The same assistant turn attaches cards, in this order when present:
   - **Listing** (inferred or claimed)
   - **Email** thread(s) that matched (compact if more than one)
   - **Person** cards for people on those threads / the next event
   - **Calendar** next event at that address (if any)
   - **Task** only if an open task already mentions the address (do not invent tasks)
3. If nothing in the cache matches, say so and show no listing card. Do not spawn sample Beach Drive.
4. If Google is disconnected, existing Connect Google path. No fake graph.

### Infer

From the last-synced cache only (Gmail / Calendar / Tasks already on disk):

- Match on address / street token in email subject, preview/body, calendar title, `location`, task title/notes.
- Fill `relatedListing` and `relatedPeople` on the matched `EmailItem` / `CalendarItem` in memory (and persist on the next cache write if cheap).
- Build a `ListingItem` with `ownership: "Inferred mine — confirm to claim"` when the address is new. Do **not** scrape MLS or public portals.
- People: name + email from the matched thread/event. Role can stay generic (“On this thread”) unless the sample/fixture already labels them.

### Claim

On an inferred listing card, user can **claim** (“that’s mine” / tap Claim):

- Ownership becomes **Mine**. Persist in the offline cache (same disk store as mail).
- Activity log: `title` claim, `outcome` recorded. Not a Google write.
- Unclaim is out of scope. Add-by-address is Phase 2.4.

Voice after claim: “Got it — Beach Drive is yours.” Listing card updates in place. No new chrome.
