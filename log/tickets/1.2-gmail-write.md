## Current code (do not invent)

- Reads shipped. Scopes are **read only**: `gmail.readonly`, `calendar.readonly`, `tasks.readonly` (`GoogleScopes.swift`). Comment already says write scopes stay off until a confirmed provider write exists.
- `DraftConfirmMachine`: only `.confirmed` may call send. `mayCallSendClient` is the gate.
- `RecordingSendClient.send`:
  - unconfirmed → `blockedUnconfirmed`
  - confirmed → enqueue `OfflineAction`, return `queuedNotDelivered`
  - `providerDelivered` is **false** on purpose (“Slice 2 leaves it false”)
- `OfflineQueue` holds confirmed writes until a provider succeeds. `flushWhenOnline()` empties the list; nothing talks to Gmail today.
- `ActivityEntry` exists (`title` / `detail` / `outcome`). Confirm today logs **queued, not delivered**.
- `DraftConfirmItem`: `actionTitle`, `channel` (already `"Gmail"` on the sample), `toLine`, `subject`, `body`, `status`.
- Silent send is a bug. Reporting “sent” without provider success is a bug. Style C locked.

## User-visible behavior

Eriq (Google connected) is in a real thread. He says **“draft a reply…”** then later **“send it” / “yes send”**.

1. **Draft** (already works): `draftConfirm` card, status `pending`. Voice does not claim it was sent. Edit / cancel still use `DraftConfirmMachine`.
2. **Send ask:** show the same card with the **exact** To / Subject / Body. No new wizard.
3. **Confirm** (tap Confirm & Send, or spoken yes after the card is up):
   - Re-auth if Gmail write scope is missing. Stay on the draft if he declines the new scope. Do not send.
   - Call Gmail send with that exact payload.
   - **Success:** card / Activity `outcome` = `delivered`. Voice: it went. Cache refresh so the sent mail can show on the next inbox ask.
   - **Failure** (network, 401, 403, 5xx, rejected payload): card stays a draft (`pending` or a failed state if you add one — do **not** use `.confirmed` as “sent”). Activity `outcome` = `failed`. Voice: it did not go; draft is still here. Never say sent.
   - **Offline:** stay `queuedNotDelivered` on Activity. Flush when back online; same success/fail rules. Queue is not delivery.
4. Unconfirmed send remains `blockedUnconfirmed`. No client call.

Calendar / Tasks writes are **1.3**. Do not add those scopes here.

### Scopes

- Add the least-privilege Gmail write needed to send a reply/new message on confirm (typically `gmail.send`). Keep the three read scopes.
- Existing dogfood users will see Google’s consent again. Connect Google copy should say we can **send** after you confirm, not that we already can.
- Do not request Calendar/Tasks write in this slice.
